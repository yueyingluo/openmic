# JYB：两阶段实现与本次累计更新

本说明以这次提供的 `openmic-main/` 为基线。它已经包含 JYB 第一次在 csw 基础上提交的表演控制；本次只准备其后的累计更新，尚未代用户上传。生产代码继续放在 `src/openmic/`，没有另建 `openmic_jyb` 包。

## 1. 谁已经做了什么

CSW 提供基础 TTS 链路：提取正文、清理标签、请求 CosyVoice2、修复 WAV Header、拒绝清理后空输入、检查 WAV 与实际采样率、返回声道/音频时长/请求耗时。原 `tts.py` 的接口和原页面保留。这些不是 JYB 的新增成果。

文本组负责 CFunSet 下载、检索、参考筛选、原作/改编策略和文本质量闭环；评估组负责自己的评估模块。JYB 复用它们的接口和来源信息，不把这些工作算成自己的检索算法、数据训练或幽默评分。

JYB 的职责是把已写好的台词及表演标记执行成音频，并让对照、失败和结果可以复查。

## 2. 第一阶段：第一次 GitHub 贡献，当前 main 已有

这一阶段对应 `jyb_run_20261026_02`，详细历史说明保留在 [JYB_CONTRIBUTION.md](JYB_CONTRIBUTION.md)。其核心不是重新写一个 TTS 模型，而是在 CSW 的请求层之上增加表演执行层。

### 稿件变成可执行事件

`tts_plan.py` 将 `<SCRIPT>` 中的正文和 `[INTRO]`、`[SETUP]`、`[PUNCHLINE]`、`[CALLBACK]`、`[PAUSE=...]`、`[EMOTION=...]`、`[SPEED=...]`、`[EMPHASIS]...[/EMPHASIS]` 编译为 `Speech` 与 `Pause`。未知标记和不合法参数直接报错。可选语气词必须统一用于所有对照条件，不能悄悄只改某一版台词。

情绪变成模型 instruction，重音变成 `<strong>` 软提示，语速变成请求参数；停顿由本地 PCM 实现。16 kHz 下，0.8 秒插入 12,800 个零采样，2 秒插入 32,000 个零采样。显式停顿覆盖相应默认值。这个精确性指“额外插入的数字静音”，不意味着模型内部停顿或词级时间戳也精确。

### 请求、拼接与对照

`tts_backends.py` 提供真实后端和无需 Key 的 tone 后端，并严格检查采样格式。`tts_render.py` 合成片段、做旧版裁边/淡入淡出、缓存 PCM、插入静音、保存 `audio.wav` / `metrics.json` / `timeline.json`。逐段 callback 表示一个完整片段已返回，不是文本/音频双流式。

| 条件 | 作用 |
|---|---|
| `baseline` | 中性、1.0 倍速、无重音、片段间普通 0.12 秒间隔 |
| `timing` | 复用中性语音，1.0 倍速、无重音，执行计划停顿 |
| `emotion` | 执行情绪提示，1.0 倍速、无重音，使用普通间隔 |
| `performance` | 执行情绪、语速、重音和计划停顿 |

`baseline` / `timing` 可共享同参数缓存，较好隔离静音变量；`performance` 同时改变多种因素，只能作为综合版本对照。固定 voice 字符串不保证每个片段的实际音色完全一致。

### 工作流、界面和验证工具

| 已在 main 中的模块 | 用途 |
|---|---|
| `tts_workflow.py`, `tts_review.py` | 复用五 Agent，规定 Writer/Coach 协议；核查正文顺序、标签及 QC，不让 Coach 重写台词 |
| `tts_cli.py`, `tts_batch.py`, `tts_app.py` | 单稿/批量/编辑预览/四条件合成入口 |
| `tts_evaluate.py` | 匿名试听、随机次序、空评分表和人工评分汇总；不生成假的评分 |
| `tts_asr_check.py` | 音频与参考文本哈希缓存、ASR 差异辅助核查 |
| `tts_acceptance.py` | WAV、时间轴、静音、同稿条件及实际时长核查 |
| `tts_showcase_app.py`, `tts_launch_showcase.py`, `tts_results_app.py` | 读取各自约定的旧结果布局，不自动生成语音 |

这些模块以及 `tts_plan.py` / `tts_backends.py` / `tts_render.py` 共 14 个生产模块，并非本次新增 14 个。原有样例、测试、运行说明和历史结果文档也已在 main。

## 3. 第二阶段：从当前 main 之后累计新增

按执行次序分为三步。没有把中间步骤的不足从历史记录中抹去。

### A. 适配组员的 CFunSet 生成结果

在本人已有的 `tts_workflow.py`、`tts_review.py`、`tts_cli.py`、`tts_batch.py`、`tts_app.py` 上更新：

1. 接收 `content_mode`、索引路径、用户 context、原作/改编选择等现有生成参数。
2. 复用同学的检索和参考筛选，保留 example IDs、source policy、参考选择和工作流 trace。
3. CFunSet 入口沿用团队自然篇幅、可选回调的创作策略，不用旧版长稿的字数/包袱/回调配额强行扩写。
4. Writer → Coach → 待合成正文仍须一致，QC、标签和原稿来源仍需检查；减少配额不等于关闭质量检查。
5. Mock 明确拒绝冒充真实 CFunSet 检索增强；手工稿只有显式 `--manual-script` 才能进入相应新入口。

这部分是“把检索生成的文本安全交给 TTS”，不是新建一套检索生成系统。原 `autogen_v02.py`、`humor_*.py` 和同学的页面/评估代码没有改写。

### B. 从情绪标签转向内容驱动的舞台执行

听评发现旧完整表演偏叙述、部分片段音色漂移。因此新增四个模块：

| 模块 | 做法 |
|---|---|
| `tts_stage_plan.py` | 规则或 LLM 仅输出注释：原文切片、意图、焦点词、边界类型；逐字校验切片完整覆盖原稿，不接受替换台词 |
| `tts_stage_render.py` | 固定 voice 与统一短 instruction，按 setup / contrast / reveal / button 等意图选择有限的速度/线性增益/停顿；重音仍是软提示 |
| `tts_stage_cli.py` | 来源检查、计划检查、缓存与锁、三种舞台对照入口 |
| `tts_stage_evaluate.py` | CPU 波形诊断、整稿响度匹配、空白 A/B 评分材料；不把声学指标当幽默/MOS |

经过试验后保留的统一 instruction 是“请轻快地说。”；速度是有界的 1.02–1.12 左右（疑问意图另有细分），不是每句换情绪或换声。它降低了请求控制上的不一致，不能证明服务输出的说话人身份不变。

中间轮的 `stage_prompt` / `stage_course` / `stage_club` 保留下来用于研究对照；其中旧裁边/淡入淡出和 80/150 ms flow/breath 间隔仍存在。它们不是最终完整性修复版。用户指出句间太紧、端点不清和漏句后，才有下一层。

### C. 先检查每一句，再交付整篇

| 模块 | 关键行为 |
|---|---|
| `tts_integrity_plan.py` | 在验证过的舞台计划上确定性分句；保留配对引号块，记录原文 Unicode `[start,end)`，完整覆盖，不把字符位置冒充词级时间戳 |
| `tts_integrity_gate.py` | 对物理句音频的 ASR 做字符对齐，分别看 CER、删除数/连续删除、首尾窗口和短句，而非仅看整稿平均 CER |
| `tts_integrity_audio.py` | 严格解析完整 WAV；检查原始首尾能量；原 PCM 全量复制；相邻句至少插入 360 ms 零采样；不裁边、不淡入淡出、不交叠、不改调、不逐句增益 |
| `tts_integrity_listening.py` | 显式审核依据的加载/核验与有限人审放行；原机器失败报告保留；没有外部依据时不沿用历史两句的豁免 |
| `tts_integrity_cli.py` | 有界候选、持久重试账本、断点恢复、拒绝漏句整稿、处理 401/402/403 等服务中断；完整通过才 assemble |

短句不超过 8 个规范化字符时要求完全一致。长句 CER 不超过 12%，删除数不超过 `floor(3% × 字数)`，连续删除不得超过 1 字，首尾最多 4 字窗口不允许删除且至多 1 次替换。规范化包括明确的数字等价，不做任意同音替换或改写；ASR 可误判，阈值通过也不能证明每个音素清晰。

端点检查看原音频最前/最后 10 ms 的 RMS，风险阈值分别 −35 / −40 dBFS；这是保守风险信号，不是“已经证明截字”。在拼接后的外部补零不会恢复模型漏读的字。因此必须先检原片段，再拼接。

最终 `safe_course` 与 `safe_club` 使用完全相同的接受句 PCM，仅插入静音不同。句间静音取句间下限、原稿停顿、适用的舞台边界和前句反应时间的最大值，不机械相加。新层即便源稿显式标零停顿，也不能取消 360 ms 质量下限。转折/反应在原舞台单元转换/结束处适用，不是每切出一句都加反应停顿。课程转折/反应为 0.8/2.0 秒；紧凑版为 0.48/0.85 秒。整稿首/尾保护分别以 0.12/0.40 秒为下限，仍须与源首/尾停顿及适用反应时间取最大值；本批尾停顿常为 2 秒。

## 4. 本次为可上传代码做的必要整理

旧实验目录中的确有两条具体人审记录、两条正字法个案和末尾标点/重音试验。不能把它们写死在通用库里，更不能把一个 `passed: true` 当新的审核依据。

上传版保留同一方法，改为显式提供审核依据；默认严格。审核绑定原稿/计划、句 ID/文本、WAV SHA、原候选与机器报告、审核文字及审核文件哈希。原机器 `False` 留存，人审不放宽尾部风险，也不默认允许任意同音差异。特殊输入变换须有明确的授权范围和有限次数，历史试验不会自动在新稿复现。精确可选参数见 [运行说明](JYB_DELIVERY_USAGE.md)。

这是去除实验路径和特例依赖，未改变“原文完整覆盖 → 逐句检查 → 原 PCM 拼接”的实现本质。历史录音来自旧实验的实际结果，本次没有重新生成，也不声称用整理后的代码再跑出了完全相同的云端波形。

## 5. 展示与事实边界

本次三版本试听固定为同一稿：11-01 运行的 `baseline`、同次 `performance`、最终完整性轮的 `safe_club`。默认食堂，可选 DDL 和健身。它不是把三个不同脚本拼在一起对比，也不包括本次重新生成的语音。

历史完整性轮共 124 句，接受 123 句：119 自动、2 正字法个案、2 用户实际核听；食堂/DDL/健身整稿可用，网购一句仍缺两个“啊”，故没有把缺句版本作为新整稿交付。食堂 31 句全部自动通过，作为默认演示更直接。

这次只为三个版本重新计算整稿响度匹配，每个版本一个固定增益，同时保留原始声音；近似过采样峰值不是经过认证的真峰值测量。响度匹配减少音量干扰，但三版本同时改变分段、提示和停顿等变量，不能据此归因单项效果或宣称 MOS 提升。

没有训练/微调 TTS，没有 learned latent、说话人嵌入训练或实跑 AutoDL；舞台意图/焦点/边界是显式控制表示。三个样本不代表已经满足课程“五主题、每篇 3–5 分钟”的全部验收。
