# 第一次项目分工会（18 分钟）

## 会议目标

在 18 分钟内确认五个人的主责、Reviewer、首个交付物和截止时间。技术方案细节不在本次会议展开。

## 会前准备

每个人会前阅读 PRD 的“本阶段范围”和“五人分工”，并准备：

- 如需调换分工，提出希望交换的对象；
- 一个明确的时间冲突或资源限制；
- 自己首个交付物可完成的日期。

## 议程

| 时间 | 内容 | 必须产出 |
|---:|---|---|
| 0–2 分钟 | 组长说明评分重点和本阶段交付物 | 统一完成标准 |
| 2–9 分钟 | 逐人确认主责；有冲突时当场交换 | 五位 Owner |
| 9–13 分钟 | 为每项工作确认 Reviewer 和接口依赖 | Review 关系与依赖清单 |
| 13–16 分钟 | 每人报首个交付物与截止时间 | 五个带日期的 GitHub Issues |
| 16–18 分钟 | 组长复述分工和下一次检查点 | 最终分工表 |

|---|---|---|---|

## 会议规则

- 对分工无异议时直接确认，不逐项讨论实现细节；
- 分工冲突只比较时间投入、技能匹配和模块依赖；
- 不能在 2 分钟内解决的技术问题，由对应 Owner 会后形成 Issue；
- 会议结束前，每个人必须拥有一个可验收、带截止时间的 Issue。
