# OpenMic 产品需求文档

- 文档状态：执行版
- 负责人：组长
- 版本：v0.2
- 课程要求：[OpenMic 项目页](https://yzhu.io/courses/core/projects/openmic/)

## 1. 项目目标

OpenMic 接收生活主题、表演风格、目标时长和目标受众，通过五个 Agent 的协作，生成 3–5 分钟中文脱口秀，并输出具有停顿、重音、语速和情绪变化的语音。

最终成果需要证明三件事：

1. 多智能体分工相较单次生成能提升内容质量或可控性；
2. CFunSet 对中文 setup-punchline、回调和口语风格产生可测量的帮助；
3. 表演控制相较普通朗读能提升语音自然度和喜剧表达效果。

## 2. 用户场景

用户输入“我的网购经历”，选择“吐槽”、3 分钟和“大学生”受众。系统生成结构化脚本，展示五个 Agent 的协作过程与质检结果，并提供可播放、可下载的表演音频。

## 3. 输入与输出

### 输入

| 字段 | 类型 | 约束 |
|---|---|---|
| `topic` | string | 非空生活主题 |
| `style` | enum | 观察 / 自嘲 / 吐槽 |
| `duration_minutes` | int | 3、4 或 5 |
| `audience` | string | 明确目标受众 |

### 输出

| 输出 | 验收要求 |
|---|---|
| Agent 轨迹 | 显示角色、处理结果、耗时与错误状态 |
| 脚本 | 标出 setup、punchline、callback，符合目标时长 |
| 表演策略 | 停顿、重音、语速、情绪能被 TTS 管线执行 |
| 质检结果 | 给出幽默度、文化适配、结构完整性和修改结论 |
| 音频 | 16 kHz WAV，可播放、可下载 |

## 4. Agent 职责与协作协议

| Agent | 输入 | 输出 | 验收标准 |
|---|---|---|---|
| ComedyDirector | 用户需求 | 主题扩展、叙事主线、风格边界 | 策略可直接约束后续创作 |
| AudienceAnalyzer | 用户需求、创作策略 | 共鸣点、语言偏好、风险提示 | 建议具体且与受众相关 |
| JokeWriter | 策略、受众结论、CFunSet 样例 | 结构化脚本 | 有 setup-punchline 和至少一次回调 |
| PerformanceCoach | 结构化脚本 | 可执行的表演指令 | 每个核心笑点具备节奏或情绪设计 |
| QualityController | 全部中间结果 | 结构化评分和修改意见 | 评分可解析、结论可触发重写 |

QualityController 判定需要修改时，流程返回 JokeWriter，并再次经过 PerformanceCoach。单次请求最多重写 2 次。

## 5. 本阶段范围

### P0

1. **CFunSet 数据管线**
   - 核对许可证和可公开范围；
   - 完成清洗、样本统计和训练/验证划分；
   - 实现可复现的示例检索或数据构造；
   - 记录数据处理参数和随机种子。

2. **中文幽默生成实验**
   - 建立无 CFunSet 的 Prompt baseline；
   - 实现一种 CFunSet 增强方案：检索增强、few-shot 或 LoRA；
   - 对比 setup-punchline、回调、口语化和文化适配表现；
   - 固定不少于 5 个测试主题，保存完整生成轨迹。

3. **语音表演控制**
   - 将停顿时长、重音、语速和情绪转换为可执行参数或稳定文本协议；
   - 重点验证包袱前约 0.8 秒停顿、笑点后约 2 秒停顿；
   - 比较普通朗读与表演控制版本；
   - 统计采样率、音频时长、生成耗时和实时率。

4. **评测与实验记录**
   - 固定自动评分 JSON Schema；
   - 建立人工盲评表，覆盖幽默度、自然度、停顿合理性、重音准确性和情感表达；
   - 报告评价人数、均值、方差及典型失败案例；
   - 比较单 Agent、多 Agent、CFunSet 增强和表演控制四组条件。

5. **课程交付**
   - 5 个不同主题的 3–5 分钟音频样本；
   - 技术报告，包括架构、方法、实验设置、结果和局限；
   - 10 分钟演示视频；
   - 可复现实验命令和演示检查清单。

### P1

- LoRA 与检索增强的对照实验；
- 失败阶段的局部重试与缓存；
- 多音色或多 TTS 模型对比；
- 自动生成实验图表和结果页面。

## 6. 验收指标

| 类别 | 指标 | 目标或报告方式 |
|---|---|---|
| 内容 | 脚本时长 | 3–5 分钟 |
| 内容 | 结构完整性 | 每个样本包含 setup-punchline，至少一次 callback |
| 内容 | 幽默度、文化适配 | 盲评并报告均值与方差 |
| 语音 | 采样率 | 16 kHz |
| 语音 | 实时率 | 大于 1.0x |
| 语音 | 表演效果 | 与普通朗读做盲评对照 |
| 系统 | 端到端响应时间 | 小于 30 秒，并注明统计边界 |
| 系统 | 稳定性 | 5 个固定主题连续运行无崩溃 |

## 7. 五人分工

| 人员 | 主责 | 交付物 | Reviewer |
|---|---|---|---|
| 组长 / 成员 A | 系统集成与实验编排 | 跨模块协议、实验配置、延迟优化、可演示版本 | 成员 E |
| 成员 B | CFunSet 与幽默生成 | 数据说明、检索或训练管线、Prompt baseline、内容对照实验 | 成员 D |
| 成员 C | TTS 与表演控制 | 节奏/情绪控制管线、普通朗读对照、音频性能统计 | 组长 |
| 成员 D | QualityController 与评测 | 评分 Schema、自动评测、人工盲评、结果分析 | 成员 B |
| 成员 E | 结果呈现与课程交付 | 实验对比展示、五个样例包、技术报告整合、演示视频 | 成员 C |

每个成员对自己的交付物负责，Reviewer 在合并前检查可复现性、接口兼容性和验收证据。跨模块问题由组长决策。

## 8. 里程碑

| 里程碑 | 目标 | 退出条件 |
|---|---|---|
| M1 数据与内容实验 | 得到可复现的 CFunSet 增强结果 | 固定数据划分、5 个主题、baseline 与增强方案结果齐全 |
| M2 表演与评测 | 验证语音表演控制的效果 | 普通朗读与表演版音频、自动指标和盲评结果齐全 |
| M3 最终交付 | 完成课程验收材料 | 代码、5 个音频、技术报告和 10 分钟视频齐全 |

具体截止日期由第一次分工会写入 GitHub Milestone。

## 9. 风险与处理

| 风险 | 处理方式 |
|---|---|
| CFunSet 许可或获取受限 | 先完成许可证核对，只使用允许公开的样本和统计信息 |
| 串行调用超过 30 秒 | 缓存重复结果，并行受众分析与数据检索，限制重写次数 |
| “好笑”评价主观 | 固定盲评题目、随机播放顺序，并同时报告均值与方差 |
| TTS 不支持精确控制 | 将标记映射为分句生成与静音拼接，并保留普通朗读对照 |
| 模型输出格式漂移 | 使用结构化协议、解析校验和有限次数重试 |

## 10. 非目标

- 生产级账号、权限和高并发系统；
- 无限制的 Agent 自由讨论；
- 未经验证的数据或模型权重公开发布；
- 为增加技术栈数量而引入与评分无关的服务。
